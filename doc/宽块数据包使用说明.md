# 宽块数据包使用说明（`sr_datafeed_logic.block_bytes`）

> 面向：新机型驱动（125 MHz × 128 bit）的作者
> 一句话：`LA_CROSS_DATA` 的「每通道每拍多少字节」由 `block_bytes` 上报，不填 = 8
> 契约实现：`libsigrok/include/libsigrok/libsigrok.h` 的 `struct sr_datafeed_logic`、
> `libsigrok/src/session.c` 的 `sr_session_send()`、`LogicSnapshot::append_cross_payload()`

给**驱动侧**看的一页纸：怎么声明「每个通道每拍占多少字节」，以及接收端会怎么解析。

## 一句话

`LA_CROSS_DATA` 的 payload 是 `[ch0 一块][ch1 一块]…[chN-1 一块]` 循环。一块 = 一拍硬件。
**每通道每块多少字节**由 `sr_datafeed_logic.block_bytes` 给出；不填就是 8。

| 值 | 硬件 | 一块 |
|---|---|---|
| 8（缺省） | 250 MHz × 64 bit | 64 样本/通道 |
| 16 | 125 MHz × 128 bit | 128 样本/通道 |
| 合法区间 | 8 的倍数，`[8, 8192]` | `W = block_bytes / 8` 个 u64 槽 |

`length` 仍是**总字节数**；每通道样本数 = `length * 8 / channel_num`，与块宽无关。

## 最小用法

驱动侧就一行 —— 在发 `SR_DF_LOGIC` 之前把宽度填上：

```c
struct sr_datafeed_logic logic = {0};   /* 必须清零：不清零其余字段是栈垃圾 */

logic.length      = data_len;           /* 总字节数，不是每通道字节数 */
logic.unitsize    = 1;                  /* CROSS 下无意义，填 1 即可 */
logic.format      = LA_CROSS_DATA;
logic.block_bytes = 16;                 /* ← 每通道每拍 16 字节（128 样本） */
logic.data        = buf;

packet.type    = SR_DF_LOGIC;
packet.payload = &logic;
sr_session_send(sdi, &packet);
```

**不需要改接收端。** `LogicSnapshot::append_cross_payload()` 已经按
`W = block_bytes / 8` 做 W 宽块的 u64 转置，`W == 1` 走的是原来的单 u64 快路径。

## 三条硬规则

1. **一个块不能窄于 8 字节。** 快照树的最小单位是 u64（= 64 样本），块宽必须是它的整数倍。
   4 字节块（32 样本）表达不了，会被当成非法值退回 8。
2. **payload 必须按整块对齐**：`length` 是 `channel_num * block_bytes` 的整数倍。
   不足一块的尾巴会被异步 writer 直接截掉（防通道错位）。
3. **块宽是"每拍字节数"，不是采样率。** 同一台设备在 250 MHz / 125 MHz 下块宽相同 ——
   它由 FPGA 位宽决定，别从 `cur_samplerate` 去推。

## 例子

16 通道、`block_bytes = 16`、发 2 个块：

```
length = 16 * 16 * 2 = 512 字节
布局   = [ch0 16B][ch1 16B]…[ch15 16B]   ← 第 1 块，每通道 128 样本
         [ch0 16B][ch1 16B]…[ch15 16B]   ← 第 2 块
每通道样本数 = 512 * 8 / 16 = 256
```

`ch0` 第 1 块的 16 字节落在 `buf[0..16)`，第 2 块落在 `buf[256..272)`。

## 四条别做

- **别用 `unitsize` 表达块宽。** `unitsize` 是 `LA_SPLIT_DATA` 的「每样本组字节数」，
  CROSS 下接收端直接忽略。
- **别做成 `SR_CONF_*` 设备配置。** 它是**每包**属性（USB HS/SS 都可能不一样），
  做成配置还要写进 `.pxl` 头，且必须两侧同步。
- **别在老驱动里加分支。** 上游 80+ 个 sigrok 驱动全走 `LA_SPLIT_DATA`，不读这个字段，
  不用改也不用管。
- **别在 `pxlogic.c` 里按型号分派块宽。** pxlogic 只服务 250MHz×64bit 机型，固定 8；
  128bit 的新机型有自己的驱动，在那边赋值。

## 填错了会怎样

| 情况 | 行为 |
|---|---|
| 不填 / 填 0 / 填非法值（如 5、12、8193） | 按 8 解析。**不会崩**，但 16 字节的包会被当成 8 字节解 → 通道串位 |
| 填了合法值但 `length` 不是整块倍数 | 异步 writer 截掉不足一块的尾巴，其余正常 |
| 宽块（>8）且上一条 payload 留了半个 u64 残留 | 判为非法状态，**整条丢弃 + `pxv_err`**，不静默错位 |

第 1 条是唯一会「悄悄画错」的：`session.c` 的归一化只能挡住非法值，挡不住
「合法但填错了」。填完记得对一遍波形。

## 自测

`tests/qtest/data/test_logic_snapshot_cross_alignment.cpp` 里的 `build_cross_wide(N, blocks, B)`
就是任意块宽的负载构造器，`expected_bit(c, s)` 对任何块宽都成立（样本 s 永远在全局槽
`s/64` 的第 `s%64` 位）。加用例照抄 `check_wide_cross(N, blocks, B)` 即可。

反向验证：把接收端的 `block_bytes` 强制改成 8，宽块用例必须**确定性失败**
（首个失配点是 `ch=0 s=64`，即第二个 64 样本槽）。
